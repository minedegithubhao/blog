Eval Set：普通列表还是生成向导

本轮确认 clean JSON 到测试案例的页面结构

A. Case List First
Eval Set Header + Add Case
Filters: label / difficulty / enabled
Case Table
B. Generation Workbench + Auditable Cases
1. Select Dataset Version
2. Choose Case Strategy
3. Preview Distribution
4. Generate Cases
Generation Summary: source, labels, difficulty, count
Auditable Case Table: query, expected, source ref, scoring profile
Actions: Edit / Disable / Run Evaluation
我的建议：B. Generation Workbench + Auditable Cases
  • Eval Set 的关键价值不是存 case，而是把 clean JSON 变成可解释、可复用、可评估的 case。
  • 生成向导能显式记录生成策略，例如标准问法、改写问法、错别字、越界问题、无答案问题。
  • 可审计表能让人工修改 case，同时保留 source ref 和 scoring profile，后续 verdict 才有可信度。

B 的收益

  • 从数据到评估的链路完整
  • case 生成策略可复盘
  • 一键 Run Evaluation 有明确入口

A 的代价

  • 只像维护表格，不像生成评测集
  • case 来源和策略容易丢失
  • 后续指标异常时难解释样例构成
