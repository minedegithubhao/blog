B. 分区表单 + 冻结摘要

按 RAG 阶段配置，每次 run 引用冻结版本，天然服务可复跑和可比较。

我的建议：B. Sectioned Form + Frozen Summary
  • 当前产品目标是比较 RAG 策略优劣，而不是开放任意 DAG 编排。
  • 分区表单能把建库、检索、召回、重排、prompt、fallback 的参数清晰固定下来。
  • 右侧冻结摘要让用户在保存前看到“这个 pipeline version 到底改了什么”。

B 的收益

  • 版本语义清楚
  • 更容易做 diff 和复跑
  • 配置校验边界明确

A 的代价

  • 视觉上强，但实现和测试成本高
  • 容易偏离 FAQ RAG 评估主线
  • 版本冻结和参数 diff 会更复杂
