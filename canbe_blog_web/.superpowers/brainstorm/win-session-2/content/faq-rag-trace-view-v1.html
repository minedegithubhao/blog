Trace View：排查路径怎么组织

本轮确认单个 case 的 trace 页面结构

A. Horizontal Pipeline
Query
Retrieve
Rerank
Generate
Score
Selected Stage Details
B. Stage Timeline + Evidence Panel
Input
Chunk Match
Recall
Rerank
Generation
Scoring
Case Summary + Failure Hypothesis
Evidence: retrieved chunks / scores / citations
Answer + metric judgement
我的建议：B. Stage Timeline + Evidence Panel
  • Trace View 的主要问题是定位责任阶段，而不是展示一条漂亮流水线。
  • 左侧阶段列表能自然承载错误标记，例如 recall miss、rerank drop、generation hallucination。
  • 右侧证据面板能保留足够空间展示 chunk、score、citation 和 answer 对比。

B 的收益

  • 更适合工程排障
  • 可以逐阶段挂载失败假设
  • 移动端也更容易折叠成上下结构

A 的代价

  • 横向空间很快不够
  • 复杂证据会挤到下方，读起来断裂
  • 更像流程展示，不像排障工作台
